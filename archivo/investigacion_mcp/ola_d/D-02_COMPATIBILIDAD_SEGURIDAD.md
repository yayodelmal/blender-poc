## Reporte de socket #404 y exposición

La auditoría SEC-001/002 confirma que #404 declara versión 1.6.0, especifica `exec()` sin autenticación y reporta reproducción inocua. El panel consultado indica no hay branch/PR enlazados. La página GitHub de Releases afirma que no hay releases; el pyproject de `main` declara 2.2.6, pero no se recuperó tag, SHA completo ni artefacto. El cliente `server.py` de `main` usa host localhost por defecto y admite `--host`/`BLENDER_HOST`, pero ello no demuestra el `bind()` del addon. La revisión web no permitió verificar handler/parser/auth del addon incluido. **Aplicabilidad a 2.2.6 y existencia de fix quedan inconclusas.** Ver [SEC-001](seguridad/SEC-001_AUDITORIA_MCP.md), [SEC-002](seguridad/SEC-002_ANALISIS_ISSUE_404.md) y [SEC-004](seguridad/SEC-004_DICTAMEN_EXP001.md). No ejecutar EXP-001 con este dictamen.

Mitigaciones candidatas **para estudiar, no aplicar en esta ola**: usar solamente listener loopback si el código lo confirma; no exponer puerto a LAN/Internet, no usar túneles/port forwarding; firewall local y usuario/sesión macOS de mínimo privilegio; cerrar Blender/addon/servidor al terminar; escena desechable y backup; deshabilitar herramientas no necesarias (p. ej. importación externa) cuando configurable; revisar telemetría y desactivarla conforme política del responsable. Estas medidas reducen exposición, no convierten código Python arbitrario en sandbox ni ofrecen autenticación si el socket carece de ella. Si el bind no es loopback o el issue sigue aplicando sin mitigación aceptable, **no ejecutar EXP-001** hasta elegir versión corregida o alternativa aprobada.

No se debe enviar secretos, datos personales ni archivos privados a la escena. Ejecutar solo operaciones de lectura en EXP-001. Hacer inspección de código estática del release antes de conexión; no se realizó todavía.
